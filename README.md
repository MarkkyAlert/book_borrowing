# 📚 ระบบยืมคืนหนังสือ — คู่มือฉบับเข้าใจง่าย

> เอกสารนี้เขียนสำหรับ **คนที่ไม่ได้เขียนโค้ดเอง**
> อ่านจบแล้วจะรู้ว่า "ระบบนี้คืออะไร, ทำงานยังไง, แก้ตรงไหนได้, ตรงไหนห้ามแก้"
> ไม่ต้องเก่งโค้ดก็อ่านเข้าใจได้

---

## 1️⃣ ระบบนี้คืออะไร?

### อธิบายแบบง่ายที่สุด

ลองนึกภาพ **ห้องสมุดเล็กๆ** ที่ใช้สมุดจดว่าใครยืมอะไรไป

ระบบนี้ก็เหมือน **สมุดจดเล่มนั้น แต่อยู่บนเว็บ** — ทำทุกอย่างให้อัตโนมัติ:

| แบบเดิม (จดด้วยมือ) | แบบใหม่ (ระบบนี้) |
|---------------------|-------------------|
| จดชื่อคนยืมลงสมุด | กดปุ่ม "ยืม" — ระบบบันทึกให้ |
| นับวันเกินกำหนดเอง | ระบบคำนวณค่าปรับให้อัตโนมัติ |
| นับจำนวนหนังสือเอง | ระบบนับ stock ให้ — หมดก็บอก "หมด" |
| จำไม่ได้ว่าใครยืมอะไร | ค้นหาได้ทันที + มีรายงานสรุป |
| ใครจะจองก็โทรมา | สมาชิกกดจองเองผ่านเว็บ |

### ระบบนี้ช่วยแก้ปัญหาอะไร?

- **ลืมจด** → ระบบจดให้ทุกรายการ
- **นับ stock ผิด** → ระบบหักจำนวนอัตโนมัติ
- **คำนวณค่าปรับผิด** → ระบบคิดให้ตามจำนวนวันที่เกิน
- **ไม่รู้ว่าใครยืมอะไรอยู่** → ดูได้ทันที + มีรายงาน
- **อยากให้สมาชิกจองเอง** → มีระบบจองผ่านหน้าเว็บ

### เหมาะกับใคร?

- ✅ **นักเรียน / นักศึกษา** — ส่ง project จบ
- ✅ **คนอยากเรียนรู้ PHP** — เห็นตัวอย่างจริงของระบบจริง
- ✅ **คนอยากเดโม** — โชว์ให้ลูกค้าหรืออาจารย์ดู
- ✅ **ห้องสมุดเล็กๆ / ร้านเช่าหนังสือ** — ผู้ใช้ไม่เกิน 100 คน

### ไม่เหมาะกับใคร?

- ❌ **ห้องสมุดมหาวิทยาลัย** — หนังสือเป็นแสน ระบบไม่ได้ออกแบบมารับ
- ❌ **ผู้ใช้พร้อมกันหลายร้อยคน** — PHP ไม่เหมาะกับ scale ระดับนั้น
- ❌ **ต้อง online 24/7 ไม่มีวันล่ม** — ไม่มีระบบสำรอง
- ❌ **ต้องมี mobile app** — ตอนนี้เป็นเว็บอย่างเดียว
- ❌ **ต้องรองรับหลายภาษา** — มีแค่ภาษาไทย

## 2️⃣ ภาพรวมการทำงานของระบบ

### ใครใช้ระบบนี้บ้าง?

ระบบแบ่งคนใช้เป็น 3 กลุ่ม:

| กลุ่ม | คือใคร | ทำอะไรได้ |
|-------|--------|----------|
| **Admin** | ผู้ดูแลระบบ | ทำได้ทุกอย่าง + ตั้งค่าระบบ + ดูรายงาน |
| **Staff** | เจ้าหน้าที่ห้องสมุด | จัดการหนังสือ, สมาชิก, ยืม-คืน, จอง, ค่าปรับ |
| **Member** | สมาชิกทั่วไป | ดูหนังสือ, จองหนังสือ, ดูประวัติตัวเอง |

> 💡 Admin กับ Staff เข้าหน้าจัดการเหมือนกัน แต่ Admin ทำได้มากกว่า (เช่น ตั้งค่าระบบ, ดูรายงาน)

### ระบบทำงานยังไง? (อธิบายแบบไม่ใช้ศัพท์เทคนิค)

เวลาคุณ **กดปุ่มอะไรก็ตาม** บนเว็บ ข้อมูลจะผ่าน 4 ขั้นตอนเบื้องหลัง:

```
👤 คุณกดปุ่มบนเว็บ
      │
      ▼
📋 "พนักงานต้อนรับ" (Controller)
      │  รับคำขอ → ตรวจว่า login แล้วไหม → มีสิทธิ์ทำไหม → ส่งต่อ
      ▼
🧠 "ผู้จัดการ / สมอง" (Service)
      │  คิด → ตัดสินใจ → บังคับใช้กฎ → สั่งบันทึก
      ▼
🗄️ "พนักงานคลัง" (Repository)
      │  ไปหยิบข้อมูลจากตู้เก็บเอกสาร (database) → ส่งกลับ
      ▼
💾 ตู้เก็บเอกสาร (Database)
      เก็บข้อมูลทั้งหมดอย่างถาวร
```

### เปรียบเทียบกับร้านอาหาร

ระบบนี้ทำงานเหมือนร้านอาหาร:

- **Controller = พนักงานรับออเดอร์**
  รับคำสั่งจากลูกค้า ตรวจบัตรสมาชิก ส่งต่อให้ครัว
  ตัวอย่างไฟล์: `login.php`, `admin/borrows.php`

- **Service = พ่อครัว**
  ตัดสินใจว่าทำได้ไหม (วัตถุดิบพอไหม? เมนูนี้มีไหม?) แล้วลงมือทำ
  ตัวอย่างไฟล์: `app/Services/BorrowService.php`

- **Repository = พนักงานคลัง**
  ไปหยิบวัตถุดิบจากตู้เย็น (database) ตามที่พ่อครัวสั่ง
  ตัวอย่างไฟล์: `app/Repositories/BookRepository.php`

### ทำไมต้องแยกเป็นชั้นๆ?

คำตอบสั้นๆ: **แยกหน้าที่ให้ชัด แก้ง่าย พังยาก**

| ถ้าอยากเปลี่ยน... | แก้แค่ตรงนี้ |
|-------------------|-------------|
| หน้าตาเว็บ | ไฟล์ .php ที่ root หรือ admin/ |
| กฎธุรกิจ (เช่น ยืมได้กี่เล่ม) | ไฟล์ `.env` หรือ Service |
| วิธีดึง/บันทึกข้อมูล | Repository |

ไม่ต้องไปยุ่งกับส่วนอื่น ลดโอกาสทำพังแบบลูกโซ่

### มือใหม่ควรรู้: ตรงไหน "แก้ได้" ตรงไหน "ห้ามยุ่ง"

#### 🟢 แก้ได้สบายใจ

| โฟลเดอร์/ไฟล์ | แก้อะไรได้ |
|---------------|-----------|
| `.env` | เปลี่ยนชื่อระบบ, วันยืม, ค่าปรับ, รหัส DB |
| `css/` | เปลี่ยนสี, font, หน้าตาเว็บ |
| `includes/header.php` | เปลี่ยนโลโก้, เมนู |
| `admin/header.php` | เปลี่ยนเมนู admin |

#### 🟡 แก้ได้ถ้าเข้าใจ (ระวังหน่อย)

| โฟลเดอร์/ไฟล์ | ต้องระวังอะไร |
|---------------|-------------|
| ไฟล์ .php ที่ root (เช่น `login.php`) | ถ้าแก้ส่วน form ก็ OK แต่อย่าแก้ส่วนตรวจสิทธิ์ |
| `admin/*.php` | ถ้าแก้ส่วนแสดงผลก็ OK แต่อย่าแก้ส่วน POST handler |

#### 🔴 ห้ามแก้ถ้าไม่เข้าใจจริงๆ

| โฟลเดอร์/ไฟล์ | ถ้าแก้ผิดจะเกิดอะไร |
|---------------|-------------------|
| `bootstrap.php` | **ระบบทั้งหมดพัง** — ทุกหน้าโหลดไฟล์นี้ก่อน |
| `includes/config.php` | **ค่าตั้งค่าหาย** — ระบบทำงานผิดพลาด |
| `includes/db.php` | **เข้า database ไม่ได้** — ทุกอย่างหยุดทำงาน |
| `includes/functions.php` | **ฟังก์ชันพื้นฐานหาย** — login ไม่ได้, ระบบพัง |
| `app/Services/` | **กฎธุรกิจเสียหาย** — ยืม-คืนพัง, ค่าปรับผิด, stock เพี้ยน |
| `app/Repositories/` | **SQL ผิด** — ข้อมูลหาย/เพี้ยน |
| `.htaccess` | **ความปลอดภัยหาย** — คนอื่นเข้าถึง config ได้ |

## 4️⃣ Flow สำคัญของระบบ

### 🔑 Flow: Login (เข้าสู่ระบบ)

```
ผู้ใช้เปิดหน้า login → กรอก email + password → กดเข้าสู่ระบบ

ขั้นที่ 1 — ตรวจ input
├── email ว่างไหม? password ว่างไหม?
└── ถ้าว่าง → หยุดทันที แสดง error

ขั้นที่ 2 — ตรวจจำนวนครั้ง (rate limit)
├── ลองผิดมาแล้วกี่ครั้ง?
├── ถ้าเกิน 5 ครั้งใน 15 นาที → ล็อค! "กรุณารอ 15 นาที"
└── ทำไมต้องมี: ป้องกันคนเดารหัสผ่านอัตโนมัติ

ขั้นที่ 3 — ตรวจ email + password
├── หาผู้ใช้ที่มี email ตรงกัน
├── เอา password มาเทียบ
├── ถ้าผิด → แสดง "อีเมลหรือรหัสผ่านไม่ถูกต้อง"
│   (ไม่บอกว่าอะไรผิด — ป้องกันคนมาเช็คว่า email นี้มีในระบบไหม)
└── นับจำนวนครั้งที่ผิด +1

ขั้นที่ 4 — สำเร็จ!
├── ล้างจำนวนครั้งที่ผิด
├── สร้างบัตรผ่าน (session) ใหม่
├── ถ้าเป็น admin/staff → ไปหน้าจัดการ
└── ถ้าเป็น member → ไปหน้าแรก
```

**ทำไมต้องมีขั้นตอนเหล่านี้?**
- Rate limit → ป้องกันคนร้ายเดารหัสผ่านด้วยโปรแกรมอัตโนมัติ
- Error message กลางๆ → ไม่ให้คนร้ายรู้ว่า email ไหนมีในระบบ
- สร้าง session ใหม่ → ป้องกันแอบใช้ session เก่าโจมตี

### 📝 Flow: Register (สมัครสมาชิก)

```
ผู้ใช้เปิดหน้าสมัคร → กรอกข้อมูล → กดสมัคร

ขั้นที่ 1 — ตรวจข้อมูล
├── ชื่อ → ไม่ว่าง, ไม่เกิน 100 ตัวอักษร
├── email → ถูกรูปแบบ, ไม่ซ้ำกับคนอื่น
├── เบอร์โทร → ถ้ากรอกต้อง 9-10 หลัก
├── password → ยาวอย่างน้อย 6 ตัว
└── ยืนยัน password → ต้องตรงกัน

ขั้นที่ 2 — บันทึก
├── เข้ารหัส password (hash) ก่อนเก็บ
├── บันทึกลง database เป็น role "member"
└── ไปหน้า login + แสดง "สมัครสำเร็จ"
```

**ทำไมต้อง hash password?**
password ถูกเข้ารหัสก่อนเก็บ แม้มีคนเจาะ database ก็ **อ่านรหัสผ่านจริงไม่ออก**

### 📖 Flow: ยืมหนังสือ (Create Borrow)

```
Staff เปิดหน้ายืม → เลือกผู้ยืม + หนังสือ → กดบันทึก

ขั้นที่ 1 — ตรวจสิทธิ์
├── เป็น Staff/Admin ไหม?
└── ถ้าไม่ใช่ → ไม่ให้เข้า

ขั้นที่ 2 — ตรวจกฎ
├── สมาชิกคนนี้ยืม+จอง เกิน 3 เล่มหรือยัง?
│   (นับรวมทั้งที่ยืมอยู่ + ที่จองไว้รอรับ)
├── หนังสือแต่ละเล่มยังว่างไหม?
└── ยืมเล่มเดิมซ้ำหรือเปล่า?

ขั้นที่ 3 — บันทึก
├── หัก stock หนังสือ (available ลด 1)
├── สร้างบันทึกการยืม (กำหนดคืนตามจำนวนวันที่ตั้งไว้)
└── แสดง "ยืมสำเร็จ X เล่ม กำหนดคืน: วัน/เดือน/ปี"
```

**ทำไมต้องนับรวมการจอง?**
ถ้านับแค่ที่ยืม สมาชิกอาจยืม 3 เล่ม + จองอีก 3 เล่ม = ถือครอง 6 เล่ม ซึ่งเกินกฎ

**ถ้า 2 คนกดยืมสำเนาสุดท้ายพร้อมกัน?**
ระบบจะ "ล็อค" ข้อมูลหนังสือไว้ → คนแรกได้ → คนที่สองเห็น "หนังสือหมด"

### 📕 Flow: คืนหนังสือ (Return Book)

```
Staff เปิดรายการยืม → หารายการที่ต้องคืน → กดคืน

ขั้นที่ 1 — ตรวจ
├── รายการนี้คืนไปแล้วหรือยัง?
└── ถ้าคืนแล้ว → แสดง error "คืนไปแล้ว"

ขั้นที่ 2 — คำนวณค่าปรับ
├── วันเกิน = วันคืนจริง − วันกำหนดคืน
├── ค่าปรับ = วันเกิน × 10 บาท/วัน (แก้ได้ใน .env)
└── ถ้าไม่เกินกำหนด → ค่าปรับ = 0

ขั้นที่ 3 — บันทึก
├── เปลี่ยนสถานะเป็น "คืนแล้ว"
├── เพิ่ม stock หนังสือกลับ +1
├── ถ้า Staff เลือก "จ่ายทันที" → บันทึกการชำระด้วย
└── แสดงผล "คืนสำเร็จ" (+ ค่าปรับถ้ามี)
```

### 🔖 Flow: จองหนังสือ (Reserve Book)

```
สมาชิกเห็นหนังสือบนหน้าเว็บ → กดปุ่ม "จอง"

ขั้นที่ 1 — ตรวจ
├── login แล้วหรือยัง?
├── หนังสือยังว่างไหม?
├── จองเล่มเดิมซ้ำไหม?
├── ยืมเล่มนี้อยู่แล้วหรือเปล่า?
└── ยืม+จอง เกินโควต้า 3 เล่มไหม?

ขั้นที่ 2 — บันทึก
├── หัก stock ทันที (กันไว้ให้ ไม่ให้คนอื่นยืมไปก่อน)
├── สร้างรายการจอง (หมดอายุใน 2 วัน)
└── แสดง "จองสำเร็จ กรุณามารับภายใน 2 วัน"

ขั้นที่ 3 — หลังจากจอง จะเกิด 1 ใน 3 ทาง:

ทาง 1: Staff กด "อนุมัติ"
   → ระบบสร้างรายการยืมให้อัตโนมัติ (ไม่หัก stock เพิ่ม เพราะหักไปตอนจองแล้ว)

ทาง 2: ยกเลิก (สมาชิกหรือ Staff กด)
   → คืน stock กลับ

ทาง 3: หมดอายุ (ครบ 2 วันไม่มารับ)
   → ระบบคืน stock กลับอัตโนมัติ
```

**จุดสำคัญ:** stock ถูกหักตอนจอง ไม่ใช่ตอนอนุมัติ ดังนั้นถ้ายกเลิก/หมดอายุ ต้องคืน stock กลับเสมอ

## 5️⃣ การติดตั้ง (สำหรับมือใหม่จริงๆ)

### ต้องมีอะไรก่อน?

| ซอฟต์แวร์ | ทำไมต้องมี | ที่ดาวน์โหลด |
|----------|-----------|-------------|
| **XAMPP** | ได้ PHP + MySQL + Apache ครบในตัว | [apachefriends.org](https://www.apachefriends.org/) |

> 💡 ต้องเป็น **PHP 8.1 ขึ้นไป** (ทดสอบจริงบน 8.2 และ 8.5)
> ถ้าใช้ XAMPP อยู่แล้ว ตรวจเวอร์ชันจากหน้า XAMPP Control Panel
> ⚠️ PHP 8.0 หมดอายุ security support ตั้งแต่ พ.ย. 2023 — ไม่แนะนำแม้โค้ดจะรันได้

### ติดตั้งทีละขั้น

**ขั้นที่ 1 — วางไฟล์**
```
1. ดาวน์โหลดโค้ดทั้งหมด (หรือ unzip)
2. วางโฟลเดอร์ book_borrowing ไว้ที่:
   C:\xampp\htdocs\book_borrowing\
3. ตรวจว่าไฟล์ index.php อยู่ที่:
   C:\xampp\htdocs\book_borrowing\index.php
```

**ขั้นที่ 2 — สร้างไฟล์ .env**
```
1. เปิดโฟลเดอร์ book_borrowing
2. หาไฟล์ .env.example
3. Copy แล้วเปลี่ยนชื่อเป็น .env
4. เปิดไฟล์ .env ด้วย Notepad
5. ปกติไม่ต้องแก้อะไร (ค่าเริ่มต้นใช้ได้กับ XAMPP)
   ยกเว้นถ้า MySQL มี password → แก้ DB_PASS=รหัสของคุณ
```

**ขั้นที่ 3 — เปิด XAMPP**
```
1. เปิด XAMPP Control Panel
2. กด Start ที่ Apache (ต้องขึ้นสีเขียว)
3. กด Start ที่ MySQL (ต้องขึ้นสีเขียว)
```

**ขั้นที่ 4 — ติดตั้งระบบ**
```
1. เปิด browser
2. ไปที่ http://localhost/book_borrowing/install.php
3. กรอก email admin (หรือใช้ค่าเริ่มต้น admin@library.com)
4. กรอก password admin (ขั้นต่ำ 6 ตัว — ถ้าเว้นว่าง ระบบสร้างให้)
5. กด "เริ่มติดตั้ง"
6. ✅ ถ้าสำเร็จ จะเห็น email + password ของ admin
   ⚠️ จดไว้! ถ้าลืมต้องไปแก้ใน database
7. กดเข้าหน้าแรก หรือเข้า Admin ได้เลย
```

### Error ที่มือใหม่เจอบ่อย

| เห็นอะไร | แปลว่า | แก้ยังไง |
|---------|--------|---------|
| **หน้าขาว / ไม่มีอะไรเลย** | PHP มี error แต่ไม่แสดง | เปิดไฟล์ `.env` → แก้ `APP_DEBUG=true` → refresh |
| **Access denied for user 'root'** | รหัส database ผิด | เปิด `.env` → แก้ `DB_PASS` ให้ตรง |
| **Unknown database 'book_borrowing'** | ยังไม่ได้ติดตั้ง | ไปที่ `http://localhost/book_borrowing/install.php` |
| **404 Not Found** | วางโฟลเดอร์ผิดที่ | ตรวจว่า `C:\xampp\htdocs\book_borrowing\` มี `index.php` |
| **Apache ไม่ Start (port 80 ถูกใช้)** | โปรแกรมอื่นใช้ port 80 อยู่ | ปิด Skype หรือ IIS แล้วลองใหม่ |
| **Class not found** | autoloader พัง | ตรวจว่ามีโฟลเดอร์ `app/Services/` และ `app/Repositories/` |

## 6️⃣ การตั้งค่า (Config)

### ไฟล์ config อยู่ตรงไหน?

ค่าตั้งค่าทั้งหมดอยู่ในไฟล์ **`.env`** ที่ root ของโปรเจค

> 💡 ไฟล์ `.env` เป็นไฟล์ข้อความธรรมดา เปิดด้วย Notepad ได้เลย
> หลังแก้ไข **ไม่ต้อง restart** อะไร แค่ refresh หน้าเว็บ

### 🔴 กฎการยืม-คืน **ไม่ต้องแก้ไฟล์** — แก้ในหน้าเว็บ

เรื่องที่บรรณารักษ์อยากเปลี่ยนบ่อยที่สุด (ยืมได้กี่วัน ค่าปรับวันละเท่าไร)
**ย้ายขึ้นหน้าเว็บแล้ว** ไม่ต้องเปิดไฟล์ ไม่ต้องเรียกช่าง

> เข้าระบบเป็นผู้ดูแล → **ตั้งค่าระบบ** → ฟอร์ม **"กฎการยืม-คืน"** → บันทึก → มีผลทันที

| ตั้งได้ | ค่าเริ่มต้น |
|---------|-----------|
| จำนวนวันยืมเริ่มต้น | 7 วัน |
| ยืมได้สูงสุด — สมาชิกทั่วไป | 3 เล่ม |
| ยืมได้สูงสุด — เจ้าหน้าที่ | 3 เล่ม |
| ค่าปรับต่อวัน | 10 บาท |
| ต่ออายุการยืมได้ | 1 ครั้ง |
| ค่าดำเนินการหนังสือหาย | 0 บาท |
| เจ้าหน้าที่ยกเว้นค่าปรับได้ไม่เกิน | 200 บาท |
| เตือน "ใกล้ครบกำหนด" ล่วงหน้า | 3 วัน |
| จองแล้วต้องมารับภายใน | 2 วัน |

หน้าเดียวกันยังตั้ง **วันที่ห้องสมุดปิด** ได้ด้วย — วันหยุดยาว วันปิดปรับปรุง
ระบบจะไม่คิดค่าปรับวันเหล่านั้น (มีผลย้อนไปถึงรายการที่ยืมไปก่อนหน้าด้วย)

> ⚠️ **ค่ากฎการยืมใน `.env` ยังอ่านอยู่ แต่เป็นแค่ชั้นสำรอง**
> ระบบอ่านเรียงกัน 3 ชั้น: **หน้าตั้งค่า → `.env` → ค่าติดตัวโปรแกรม**
> พอกดบันทึกในหน้าตั้งค่าครั้งแรก ค่าใน `.env` จะ**ไม่มีผลอีกเลย**
> ถ้าแก้ `.env` แล้วตัวเลขบนหน้าเว็บไม่เปลี่ยน สาเหตุคือข้อนี้ — ให้ไปแก้ที่หน้าตั้งค่าแทน

### ค่าที่ "ควรแก้" ในไฟล์ `.env` (เหลือเท่านี้)

```env
# ─── ชื่อระบบ (แสดงบนหน้าเว็บ) ───
APP_NAME="ระบบยืมคืนหนังสือ"
# เปลี่ยนเป็น: APP_NAME="ห้องสมุดโรงเรียนวิทยา"

# ─── URL ของระบบ ───
APP_URL=http://localhost/book_borrowing
# ถ้า deploy จริง เปลี่ยนเป็น: APP_URL=https://yourdomain.com/book_borrowing

# ─── รหัส database ───
DB_HOST=localhost
DB_NAME=book_borrowing
DB_USER=root
DB_PASS=                       # ถ้า MySQL มี password ใส่ตรงนี้
```

### ค่าที่ "ห้ามแก้" (ถ้าไม่เข้าใจจริงๆ)

```env
DB_CHARSET=utf8mb4             # ❌ แก้แล้วภาษาไทยอาจเพี้ยน
TIMEZONE=Asia/Bangkok          # ❌ แก้แล้ววันที่อาจคำนวณผิด
```

### ค่า debug (สำคัญมาก!)

```env
APP_DEBUG=true    ← 🔓 เปิด: เห็น error ชัดเจน (ใช้ตอนพัฒนา)
APP_DEBUG=false   ← 🔒 ปิด: ซ่อน error (ใช้ตอนเอาไปใช้จริง)
```

> ⚠️ **ถ้าเอาไปใช้จริง ต้องตั้ง `APP_DEBUG=false` เด็ดขาด!**
> ไม่งั้นผู้ใช้จะเห็น error ละเอียดเกินไป ซึ่งอาจเป็นช่องโหว่ความปลอดภัย

### เริ่มจากตรงไหน?

```
ขั้นที่ 1 │ เปิด browser → http://localhost/book_borrowing/
          │ จะเห็นหน้าแรกแสดงรายการหนังสือ
          │

          │
```

### ❌ ไม่เหมาะกับ

| การใช้งาน | เหตุผล |
|----------|--------|
| **ห้องสมุดมหาวิทยาลัย** | หนังสือเป็นแสน ระบบช้า |
| **ผู้ใช้พร้อมกัน 500+ คน** | PHP + session ไม่เหมาะกับ scale ใหญ่ |
| **ต้อง online 24/7** | ไม่มีระบบ failover / monitoring |
| **ต้องรองรับหลายภาษา** | ตอนนี้มีแค่ภาษาไทย |
| **ต้องมี mobile app** | ไม่มี REST API สำหรับ mobile |

### ข้อจำกัดทางเทคนิค

- **ไม่มี Composer** — ไม่ได้ใช้ package manager (ทำให้ deploy ง่ายแต่เพิ่ม library ยาก)
- **ไม่มี Framework** — เขียน PHP ล้วน (เหมาะเรียนรู้ แต่ไม่ยืดหยุ่นเท่า Laravel)
- **Session-based auth** — ไม่มี JWT / OAuth (ไม่เหมาะทำ API ให้ mobile)
- **Single server** — ไม่ได้ออกแบบสำหรับ load balancer หลาย server

### ถ้าจะเอาไปใช้จริง ต้องทำเพิ่ม

| เรื่อง | คำแนะนำ |
|--------|---------|
| **HTTPS** | ต้องใช้ SSL certificate เพื่อเข้ารหัสข้อมูลระหว่างทาง |
| **APP_DEBUG** | ต้องตั้ง `APP_DEBUG=false` เด็ดขาด |
| **install.php** | ลบทิ้งหลังติดตั้งเสร็จ |
| **Database backup** | ต้องตั้ง backup อัตโนมัติ |
| **รหัสผ่าน Admin** | เปลี่ยนจากค่าเริ่มต้นทันที (ระบบบังคับให้เปลี่ยนตอน login ครั้งแรกอยู่แล้ว) |

### 🔴 สามเรื่องที่ควรรู้ก่อนซื้อ

| เรื่อง | ความจริง |
|--------|---------|
| **ไม่มีการส่งอีเมลเลย** | **ไม่ได้ตั้งใจจะทำ** — เมลจากเครื่องที่ไม่มีโดเมนของตัวเองจะเข้าถังสแปม กลายเป็นระบบเตือนที่ทำงานบ้างไม่ทำงานบ้างโดยไม่มีใครรู้ ซึ่งแย่กว่าไม่มี · ทดแทนด้วย **ใบรายชื่อโทรตามก่อนครบกำหนด** ให้บรรณารักษ์โทร/LINE เอง และ **ผู้ดูแลตั้งรหัสผ่านให้ที่เคาน์เตอร์** (ระบบบังคับให้สมาชิกตั้งรหัสใหม่ทันทีที่เข้าใช้) |

| **เลขเรียกหนังสือเป็นข้อความอิสระ** | ตั้งใจให้กรอกรูปแบบไหนก็ได้ (ดิวอี้ หรือรหัสของห้องสมุดเอง) แลกกับการที่**เรียงลำดับแบบข้อความ** — `"10"` จะมาก่อน `"9"` |

## 🔟 คำถามที่มือใหม่ถามบ่อย (FAQ)

### ❓ ใช้ PHP เวอร์ชันอะไร?

**PHP 8.1 ขึ้นไป** (ทดสอบจริงบน 8.2 และ 8.5)
ถ้าใช้ XAMPP 8.2 ก็พร้อมใช้เลย ไม่ต้องตั้งค่าเพิ่ม

### ❓ ใช้ shared hosting ได้ไหม?

**ได้!** ถ้า hosting มี:
- PHP 8.1+
- MySQL 5.7+ หรือ MariaDB 10.3+
- Apache + mod_rewrite

วิธีทำ:
1. Upload โฟลเดอร์ทั้งหมดไปที่ `public_html/book_borrowing/`
2. แก้ `.env` ให้ตรงกับ database ของ hosting
3. เปิด `http://yourdomain.com/book_borrowing/install.php`
4. ติดตั้งเสร็จ → ลบ `install.php` ทิ้ง

### ❓ ถ้าแก้โค้ดแล้วพัง ทำยังไง?

1. **เปิด browser ดู error message** — ถ้า `APP_DEBUG=true` ใน `.env` จะเห็น error ชัดเจน
2. **ดูไฟล์ log** — อยู่ในโฟลเดอร์ `logs/`
3. **เอาโค้ดเก่ากลับ** — ถ้าใช้ Git พิมพ์ `git checkout -- ชื่อไฟล์`
4. **ถ้าพังหมด** — ลบ database ใน phpMyAdmin แล้วรัน `install.php` ใหม่

### ❓ เพิ่มฟีเจอร์เองได้ไหม?

**ได้** แต่ต้องเข้าใจโครงสร้างก่อน:

| อยากทำ | ต้องแก้/เพิ่มตรงไหน |
|--------|-------------------|
| เพิ่มหน้าเว็บใหม่ | สร้างไฟล์ .php ใหม่ + require bootstrap.php |
| เพิ่มตารางใน DB | เพิ่มใน `database/schema.sql` + สร้าง Repository |
| เพิ่ม business logic | สร้างไฟล์ใหม่ใน `app/Services/` |
| เพิ่มเมนู admin | แก้ `admin/header.php` |

> 💡 **กฎทอง:** ถ้าไม่แน่ใจ ให้สร้างไฟล์ใหม่แทนการแก้ไฟล์เดิม จะได้ไม่กระทบส่วนที่ทำงานอยู่แล้ว

### ❓ ทำไมไม่ใช้ Laravel?

ระบบนี้ตั้งใจเขียนด้วย **PHP ล้วน** เพราะ:
- **เรียนรู้ง่ายกว่า** — เห็นการทำงานจริงของ PHP ไม่มี "เวทมนตร์" ซ่อนอยู่
- **Deploy ง่าย** — แค่ copy ไฟล์ไปวาง ไม่ต้อง `composer install`
- **เหมาะสอน** — เข้าใจ Controller/Service/Repository โดยไม่ต้องเรียน framework ก่อน

### ❓ Login เข้าแล้วไม่เจอหน้า admin?

ตรวจสอบ 2 อย่าง:
1. **บัญชีของคุณเป็น role อะไร?** — ถ้าเป็น `member` จะไม่เห็น admin
2. **APP_URL ใน .env ตรงไหม?** — ถ้า URL ผิด redirect จะพลาด

### ❓ Database หาย / ข้อมูลหาย ทำยังไง?

1. ถ้ายังเข้า phpMyAdmin ได้ → ลองเปิดดูว่า database `book_borrowing` ยังอยู่ไหม
2. ถ้า database หาย → ลบไฟล์ `.installed` ในโฟลเดอร์โปรเจค แล้วรัน `install.php` ใหม่
3. ถ้าอยาก restore → ต้อง import จาก backup SQL ที่เคย export ไว้

> 💡 **แนะนำ:** Export database สำรองไว้เป็นระยะ ผ่าน phpMyAdmin → Export → SQL

### ❓ รูปปกหนังสือหายหมด?

รูปปกเก็บในโฟลเดอร์ `uploads/covers/`
ถ้าลบโฟลเดอร์นี้ → รูปหายแต่ระบบไม่พัง (แสดงเป็นรูปเปล่าแทน)

### ❓ ลืมรหัสผ่าน Admin ทำยังไง?

> 🔴 **ระบบนี้ไม่ส่งอีเมล** หน้า "ลืมรหัสผ่าน" จึงส่งลิงก์รีเซ็ตให้ไม่ได้
> ต้องแก้ที่ฐานข้อมูลเท่านั้น (ดูข้อจำกัดเรื่องอีเมลใน `docs/LIMITATIONS.md`)

แก้ตรงใน database:
1. เปิด phpMyAdmin → `http://localhost/phpmyadmin`
2. เลือก database `book_borrowing`
3. เปิดตาราง `users`
4. หา row ที่ role = admin
5. คัดลอก hash นี้ไปวางในช่อง password:
   `$2y$10$92IXUNpkjO0rOQ5byMi.Ye4oKoEa3Ro9llC/.og/at2.uheWG/igi`
   (นี่คือ hash ของคำว่า "password")
6. **ตั้งช่อง `must_change_password` เป็น `1` ในแถวเดียวกันด้วย**
   ระบบจะบังคับให้ตั้งรหัสใหม่ทันทีที่ login — กันลืมเปลี่ยนแล้วปล่อยรหัส `password` ค้างไว้
7. Login ด้วยรหัสผ่าน `password` แล้วตั้งรหัสใหม่ตามที่ระบบบังคับ
