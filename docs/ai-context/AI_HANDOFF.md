## 1. กติกาการทำงานที่เจ้าของกำหนด (สำคัญที่สุด)

### 1.1 ก่อนแก้โค้ด ต้องรายงาน 8 ข้อก่อนเสมอ

ห้ามลงมือแก้ทันที ต้องตอบให้ครบก่อน:

1. ปัญหาคืออะไร
2. Root cause อยู่ตรงไหน
3. ไฟล์ที่จะต้องแก้
4. Database ต้องเปลี่ยนหรือไม่
5. ผลกระทบต่อข้อมูลเก่า
6. ผลกระทบต่อ Report / API / Import / Export
7. Security / race condition ที่ต้องระวัง
8. วิธีทดสอบหลังแก้

### 1.2 ห้ามเคลมเกินจริง

> ห้ามใช้คำว่า "รองรับ" ถ้าจริง ๆ หมายถึง "เขียนเพิ่มได้"

ข้อนี้ใช้กับทั้งโค้ด คอมเมนต์ เอกสาร และโพสต์ขาย
ถ้าไม่แน่ใจว่าฟีเจอร์ทำได้จริงไหม → **ทดสอบก่อน อย่าเดา**

### 1.3 ห้ามทำ

- เขียน SQL ยาว ๆ ใน View — SQL อยู่ที่ Repository เท่านั้น
- Duplicate business logic หลายไฟล์
- Hard-code rule โดยไม่ตรวจ config เดิม
- ลบ Foreign Key เพื่อให้ DELETE ผ่าน
- เอา Transaction ออกจาก flow สำคัญ
- เปลี่ยน Schema แล้วไม่ตรวจ Report / Import / Export
- **rewrite โครงสร้างทั้งระบบ** — รักษาของเดิมไว้ แก้เท่าที่จำเป็น

### 1.4 ถือ Source Code เป็นหลัก

ถ้าเอกสารขัดกับโค้ด → **โค้ดถูก เอกสารผิด** ให้แจ้งเจ้าของก่อนแก้

## 3. สถาปัตยกรรม

```
Page / API  →  Service  →  Repository  →  PDO  →  MySQL
(รับ input     (กฎธุรกิจ    (SQL ทั้งหมด
 + แสดงผล)      + TX)        อยู่ที่นี่)
```

**กฎ:** SQL อยู่ Repository เท่านั้น · กฎธุรกิจอยู่ Service เท่านั้น · Page แค่รับ input กับแสดงผล

**Services (8):** Auth · Book · Borrow · Dashboard · Home · Member · Report · Reservation
**Repositories (9):** Book · Borrow · Category · PasswordReset · Payment · Report · Reservation · Settings · User

**ตาราง (10):** users · categories · books · borrows · reservations · payments ·
password_resets · rate_limits · settings · schema_migrations

### กฎที่ต้องไม่พังเด็ดขาด

```
available = quantity − (ยืมอยู่) − (จองค้าง)
```

บังคับด้วย **CHECK constraint** ในฐานข้อมูล + **row lock (`SELECT … FOR UPDATE`)** ในทุก flow ที่เขียน
ถ้าแก้อะไรที่แตะ stock **ต้องตรวจสูตรนี้หลังแก้เสมอ**

## 4. 🔴 กับดัก 8 ข้อที่เสียเวลาค้นพบมาแล้ว — อย่าเสียเวลาซ้ำ

### 4.1 FULLTEXT ธรรมดาใช้กับภาษาไทยไม่ได้

MySQL/MariaDB ตัดคำด้วย **ช่องว่าง** ภาษาไทยไม่มีช่องว่าง → ทั้งชื่อเรื่องเป็น token เดียว
ค้น `โปรแกรม` ใน `การเขียนโปรแกรม` **ไม่เจอ** (ทดสอบยืนยันแล้ว)
MariaDB ไม่มี ngram parser แบบ MySQL 8

→ ระบบใช้ **คอลัมน์เงา `books.search_tokens`** เก็บ trigram (ตัดทีละ 3 ตัวอักษร)
สร้างด้วย `buildSearchTokens()` ใน PHP **ไม่ใช่ trigger** (stored function สร้างไม่ได้บนบางเครื่อง)
· ยังคง `LIKE` ไว้กรองซ้ำเพราะ trigram มี false positive
· **หนังสือที่ INSERT ด้วย SQL ตรง ๆ จะค้นไม่เจอ** จนกว่าจะรัน `php database/rebuild_search_index.php`

### 4.2 ทดสอบ "ของที่ส่งมอบ" ไม่ใช่โฟลเดอร์ที่ทำงานอยู่

`git clone` ลงโฟลเดอร์ใหม่ที่**ชื่อไม่ใช่ `book_borrowing`** แล้วเดินตาม `../INSTALL.md` ทีละขั้น
เจอบั๊กแบบนี้มาแล้ว 4 ครั้ง — ทุกครั้ง "ผ่าน" บนเครื่องพัฒนา 100% แต่พังที่ลูกค้า:

- `.gitignore` มี `vendor/` → บล็อก `assets/vendor/` ทั้งโฟลเดอร์ commit ไปแค่ 1 ใน 38 ไฟล์
- `tests/qa_test_runner.php` ฝัง `http://localhost/book_borrowing` → โฟลเดอร์ชื่ออื่น fail 18 ข้อ
- session แชร์กันข้ามการติดตั้งบนโฮสต์เดียวกัน
- คู่มือ permission ไม่ครอบคลุม XAMPP/macOS ที่ Apache รันเป็น `daemon`

### 4.3 เทสต์ที่ "ผ่าน" ไม่ได้แปลว่าฟีเจอร์ทำงาน

เจอ 3 ครั้งในโปรเจกต์นี้ — เทสต์ยืนยันแค่ "ไม่ error" ไม่ได้ยืนยันว่า "ทำงาน":

| เทสต์ | ผ่านอยู่ | แต่ความจริงคือ |
|-------|---------|----------------|
| `EC-11` | ✅ | rate limit ของการค้นหาไม่ทำงานเลย (ยิง 200 ครั้งไม่ถูกบล็อก) |
| `CC-04c` | ✅ | จับข้อความผิดตัว ทำให้ deadlock หลุดขึ้นหน้าจอโดยไม่มีใครรู้ |

**เขียนเทสต์ให้ยืนยันผลลัพธ์ ไม่ใช่แค่ status code**

### 4.4 ห้ามใช้ `FilesMatch` กัน `.git`

`FilesMatch` ดูแค่ชื่อไฟล์ตัวสุดท้าย → `.git/objects/pack/xxx.pack` หลุดทุกกฎ
ดาวน์โหลด pack ได้ = **กู้ซอร์สโค้ดทั้งโปรเจกต์** ต้องใช้ `RedirectMatch 404 "/\.git(/|$)"`
และคืน **404 ไม่ใช่ 403** (403 = ยืนยันว่ามีอยู่จริง)

### 4.5 ล็อกติดตั้งต้องมี 2 ชั้น

`.installed` เขียนไม่สำเร็จถ้า web server รันคนละ user กับเจ้าของโฟลเดอร์
(เกิดจริงบน XAMPP/macOS ที่ Apache = `daemon`) → ตัวติดตั้งไม่ล็อกตัวเอง
**ใครก็ POST เข้า `install.php` สร้างบัญชี admin ของตัวเองได้**
→ ล็อกชั้นที่ 2 อยู่ที่ `settings.installed_at` ในฐานข้อมูล
· ลูกค้าที่อัปเกรดได้จาก migration `2026_08_28_000001`

### 4.6 rate limit มี 2 ฟังก์ชัน ต้องเรียกครบคู่

`checkRateLimit()` แค่**ตรวจ** · `incrementRateLimit()` คือตัว**บันทึก**
เรียกแค่ตัวแรก = ตัวนับเป็น 0 ตลอดกาล = rate limit ไม่ทำงาน (เคยเกิดกับ `search_books`)
· **บันทึกหลังตรวจผ่านเท่านั้น** ไม่งั้นคนที่ถูกบล็อกจะถูกบล็อกยาวขึ้นเรื่อย ๆ

⚠️ ห้องสมุดส่วนใหญ่ออกเน็ตผ่าน **IP เดียว (NAT)** → ทั้งห้องสมุดแชร์โควตากัน
ตั้งโควตาต่ำเกินไป = ลูกค้าใช้งานไม่ได้ (การค้นหาจึงตั้งไว้ 300/5 นาที ไม่ใช่ 60)

### 4.7 ห้ามพึ่ง asset จากอินเทอร์เน็ต

ลูกค้าหลายรายเป็น intranet ไม่ต่อเน็ต ไลบรารีทั้งหมดอยู่ใน `assets/vendor/` แล้ว
**ห้ามเพิ่ม `<script src="https://…">` กลับเข้ามา** — มีเทสต์ Suite 2e คุมอยู่

### 4.8 เลขบรรทัดในเอกสารเลื่อนง่าย

เอกสารอ้างเลขบรรทัดไฟล์ `.php` อยู่ ~90 จุด เพิ่มฟังก์ชันกลางไฟล์ทีเดียวเลื่อนหมด
**หลังแก้โค้ด ให้ตรวจว่าเลขบรรทัดในเอกสารยังชี้ถูก**

### เครื่องมือแยก (ไม่อยู่ในชุดหลัก — รันเองเมื่อต้องการ)

```bash
php tests/load_test.php                       # วัดผู้ใช้พร้อมกัน
php tests/fixtures/seed_test_data.php         # ข้อมูลทดสอบครบทุกเคส (L1)
php tests/fixtures/seed_school_library.php    # ห้องสมุดโรงเรียนขนาดจริง 405 เล่ม/204 คน (L2)

php tests/fixtures/seed_school_library.php --expired-only   # คืนสภาพ "จองหมดอายุค้าง" ก่อนทดสอบ
php tests/fixtures/seed_bulk_data.php --books=2000 --members=600
php tests/fixtures/seed_bulk_data.php --reset
php database/rebuild_search_index.php --check # ตรวจ index ค้นหาครบไหม
php database/migrate.php --status             # ดูสถานะ migration
```

### เขียนเทสต์ใหม่ให้ดี

1. **ยืนยันผลลัพธ์ ไม่ใช่แค่ status code** (ดู §4.3)
2. **เก็บกวาดข้อมูลตัวเองให้ครบ** — ใช้ `finally` เพื่อให้ทำงานแม้เทสต์พังกลางคัน
   วัดด้วยการนับแถวก่อน/หลังรัน ต้องเท่ากันเป๊ะ
3. **พิสูจน์ว่าเทสต์จับบั๊กได้จริง** — จงใจทำให้พัง แล้วดูว่าเทสต์ fail ไหม
   ถ้าไม่ fail แปลว่าเทสต์นั้นไม่มีประโยชน์
4. อย่า hard-code URL — ใช้ `rtrim(APP_URL, '/')`
5. อย่า hard-code ชื่อ session — ใช้ `appSessionName()`

## 7. สภาพแวดล้อมของเครื่องที่พัฒนา (macOS + XAMPP)

| เรื่อง | ค่า |
|--------|-----|
| PHP | `/Applications/XAMPP/xamppfiles/bin/php` (8.2.4) |
| MySQL | `/Applications/XAMPP/xamppfiles/bin/mysql` — user `root` ไม่มีรหัสผ่าน |
| Apache รันเป็น | **`daemon`** (ไม่ใช่ `www-data`) |
| โฟลเดอร์โปรเจกต์ | เจ้าของคือ user ปกติ → **Apache เขียนไม่ได้** |

**ผลที่ตามมา:** อัปโหลดรูปปกจะพังเงียบ ๆ จนกว่าจะให้สิทธิ์:

```bash
chmod -R +a "daemon allow read,write,delete,add_file,add_subdirectory,file_inherit,directory_inherit" uploads/ logs/
```

**ตรวจว่าได้ผลจริงต้องเปิดผ่าน browser** — รันบน CLI จะได้ `true` เสมอเพราะคนละ user
