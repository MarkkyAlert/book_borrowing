**3) ไฟล์ที่ต้องแก้**

🔎 **สำรวจแล้ว: โค้ดจริงใช้ constant กฎธุรกิจแค่ 4 ไฟล์เท่านั้น** (ที่เหลือเป็น tests/seeders)

**→ แปลว่าไม่ต้องแตะ Service เลย** ถ้าเปลี่ยนแค่ "ที่มาของค่า" ไม่เปลี่ยนชื่อ constant

ไฟล์ที่ต้องแก้จริง:
- `includes/rules.php` — **ไฟล์ใหม่** โหลดค่ากฎแล้ว `define()` (รายละเอียดข้อ 7)
- `includes/functions.php` — `require_once` ไฟล์ใหม่ที่ท้ายไฟล์
- `admin/settings.php` — เพิ่มกลุ่มฟอร์ม "กฎการยืม-คืน"
- `includes/config.php` — ย้าย 3 บรรทัดออก + เขียน comment บอกว่าย้ายไปไหน

**4) Database ต้องเปลี่ยนไหม**
**ไม่ต้องเปลี่ยน schema เลย** — ตาราง `settings` (key-value) มีอยู่แล้วและใช้งานได้จริง
มี `getSetting()` / `updateSetting()` ใน `includes/functions.php:298` พร้อมใช้

⚠️ **และจะไม่ seed ค่าลงตารางตอนติดตั้ง** — ปล่อยให้ว่างไว้ก่อน
เพื่อให้ `.env` ยังเป็นเจ้าของค่าจนกว่าลูกค้าจะกดบันทึกฟอร์มเอง (ดูข้อ 5)

**5) ผลกระทบต่อข้อมูลเก่า**
ออกแบบให้ **ลูกค้าที่อัปเกรดไม่รู้สึกอะไรเลย** ด้วยลำดับ 3 ชั้น:

```
ค่าที่ใช้จริง = settings table  →  ถ้าไม่มี ใช้ .env  →  ถ้าไม่มี ใช้ค่า default ในโค้ด
```

- ลูกค้าเก่าที่ไม่เคยเปิดหน้าตั้งค่า → ตารางว่าง → ได้ค่าจาก `.env` เป๊ะเหมือนเดิม
- ฟอร์มจะ**แสดงค่าที่ใช้อยู่จริง**เป็นค่าตั้งต้น → กดบันทึกโดยไม่แก้อะไร = ค่าไม่เปลี่ยน
- ห้ามลบค่าใน `.env` ออก — ยังต้องอยู่เป็นชั้นสำรอง

**6) ผลกระทบต่อ Report / API / Import / Export**
ไม่มี — ชื่อ constant เหมือนเดิมทุกตัว โค้ดที่เรียกใช้ไม่ต้องแก้สักบรรทัด
ชุดทดสอบและ seeder ทั้งหมดที่อ้าง `FINE_PER_DAY` / `MAX_BORROW_BOOKS` ยังทำงานได้เหมือนเดิม
(ตรวจแล้ว: ทุกไฟล์ require ตามลำดับ `config → db → functions` เหมือนกันหมด)

**7) Security / Race condition — จุดที่ต้องระวังที่สุดของข้อนี้**

🔴 **ปัญหาไก่กับไข่: `config.php` ทำงานก่อนต่อฐานข้อมูล**
ลำดับใน `bootstrap.php` คือ `config.php → db.php → functions.php` และห้ามสลับ
ค่าที่มาจากตาราง `settings` จึงอ่านตอน `config.php` ไม่ได้

**ทางออก:** แยกเป็น 2 ระดับ
- ค่าที่ต้องใช้**ก่อน**ต่อ DB (DB_*, APP_URL, session, rate limit) → อยู่ `config.php` ตามเดิม
- ค่ากฎธุรกิจ → ย้ายไป `includes/rules.php` ซึ่ง `functions.php` require ที่ท้ายไฟล์
  (จุดนั้น `getDB()` และ `getSetting()` พร้อมใช้แล้วทั้งใน bootstrap และสคริปต์ CLI —
  **ตรวจแล้วว่าทั้ง 4 สคริปต์ CLI/เทสต์ require ตามลำดับเดียวกันหมด**)

🔴 **ต้องกันตอนฐานข้อมูลล่ม**
`getSetting()` เรียก `SettingsRepository` ซึ่งต้องมี `getDB()` — ถ้า DB ล่มจะ throw
ถ้าไม่ครอบ try/catch แอปจะตายก่อนถึงหน้า 503 ที่ทำไว้ (F-32) และจะไปทำลาย F-43 ซ้ำ
→ **บังคับ:** อ่านค่าใน try/catch ถ้าพลาดให้ตกไปใช้ `.env` เงียบ ๆ

**เรื่องประสิทธิภาพ:** เพิ่ม 1 query ต่อ request (`SELECT` ~15 แถว) — อ่านทีเดียวทั้งก้อน
ห้ามยิงทีละ key และเก็บใน static ไม่ให้ซ้ำใน request เดียว

**8) วิธีทดสอบ**
- ตารางว่าง + `.env` มีค่า → ค่าที่ใช้ต้องเท่ากับ `.env` เป๊ะ (จำลองลูกค้าอัปเกรด)
- บันทึกฟอร์มโดยไม่แก้อะไร → ค่าต้องไม่เปลี่ยน
- เปลี่ยนค่าปรับเป็น 5 บาทจากหน้าจอ → คืนหนังสือเกิน 3 วัน ต้องได้ 15 บาท ไม่ใช่ 30
- เปลี่ยนโควตาเป็น 2 → สมาชิกที่ยืมอยู่ 3 เล่ม **ต้องไม่พัง** (ยืมเพิ่มไม่ได้ แต่คืนได้ปกติ)
- **ปิดฐานข้อมูล → ต้องยังได้หน้า 503 เหมือนเดิม ไม่ใช่ fatal error**
- รัน `tests/run_all_tests.php` ต้องยังผ่าน 396/396
- รัน seeder ทั้ง 3 ชั้น (L1/L2/L3) ต้องยังทำงานได้ (ใช้ constant เดียวกัน)
- ใส่ค่าติดลบ / ศูนย์ / ตัวอักษร ในฟอร์ม → ต้องถูกปฏิเสธพร้อมข้อความไทย

**ค่าที่จะย้ายขึ้นหน้าจอในเฟสนี้**

| ค่า | ตอนนี้อยู่ที่ | หมายเหตุ |
|---|---|---|
| ค่าปรับต่อวัน | `.env FINE_PER_DAY` | |
| จำนวนวันยืมเริ่มต้น | `.env DEFAULT_BORROW_DAYS` | |
| ยืมได้สูงสุดต่อคน | `.env MAX_BORROW_BOOKS` | |
| วันหมดอายุการจอง | **ฝังในโค้ด** | ต้องเพิ่ม constant ใหม่ `RESERVATION_EXPIRE_DAYS` |

**ค่าที่ยังอยู่ `.env` ต่อ:** `DB_*` · `APP_URL` · `APP_DEBUG` · rate limit ทุกตัว ·
`SESSION_LIFETIME` · `ITEMS_PER_PAGE` · `BOOKS_PER_PAGE` — เป็นเรื่องเทคนิค ไม่ใช่กฎห้องสมุด

## 1. หนังสืออ้างอิงห้ามยืมออก

**1) ปัญหาคืออะไร**
ห้องสมุดแทบทุกแห่งมีชั้นอ้างอิงที่อ่านในห้องได้อย่างเดียว (พจนานุกรม สารานุกรม แผนที่)

**2) ตอนนี้ทำอะไรแทน**
ทางเดียวคือใช้ปุ่ม "ซ่อนหนังสือ" (`is_visible = 0`) ซึ่งทำให้สมาชิก**หาไม่เจอเลย**
ผิดวัตถุประสงค์ เพราะหนังสืออ้างอิงต้องค้นเจอและเดินมาอ่านได้

- `book.php` — ซ่อนปุ่มจอง แสดงป้าย "อ่านในห้องสมุดเท่านั้น" แทน
- `admin/borrow_form.php` — ดรอปดาวน์เลือกหนังสือไม่ควรแสดงเล่มอ้างอิง (หรือแสดงแต่กดไม่ได้)
- `admin/books.php` — เพิ่มป้ายในตาราง + ตัวกรอง

**4) Database ต้องเปลี่ยนไหม**
ใช่ — `books` เพิ่ม `is_reference TINYINT(1) NOT NULL DEFAULT 0`

ไม่มี — default 0 แปลว่าหนังสือเดิมทั้งหมดยังยืมออกได้เหมือนเดิม

เกือบไม่มี — แต่ต้องเช็คที่ **Service ไม่ใช่แค่ที่หน้าจอ** เพราะ `admin/borrow_form.php`

## 2. ยกเว้น / ลดหย่อนค่าปรับ

**1) ปัญหาคืออะไร**
มีแค่ปุ่ม "รับชำระ" — ถ้าจะยกเว้นให้สมาชิก (ระบบผิดพลาด เจ็บป่วย ห้องสมุดปิดกะทันหัน)
ทำไม่ได้เลย ทางเดียวคือปล่อยค้างไว้ตลอดกาล ซึ่งไปพองอยู่ในยอดค้างชำระรวมและไม่มีวันหาย

**2) ตอนนี้ทำอะไรแทน**
ไม่มีทางที่ถูกต้อง — ที่ทำได้คือแก้ฐานข้อมูลตรง ๆ ซึ่งไม่มีร่องรอยว่าใครทำ

**3) ไฟล์ที่ต้องแก้**
- `app/Services/BorrowService.php` — เพิ่ม `waiveFine(int $borrowId, string $reason, int $waivedBy)`
- `app/Repositories/BorrowRepository.php` — เมธอดบันทึกการยกเว้น
- `admin/payments.php` — ปุ่ม "ยกเว้นค่าปรับ" + กล่องกรอกเหตุผล (บังคับกรอก)
- `app/Services/DashboardService.php` + `admin/reports.php` — ยอดค้างชำระต้องไม่นับที่ยกเว้นแล้ว

**4) Database ต้องเปลี่ยนไหม**
ใช่ — `borrows` เพิ่ม 2 คอลัมน์:
```sql
fine_waived_at   DATETIME     NULL
fine_waived_by   INT          NULL   -- FK users(id) ON DELETE SET NULL
fine_waived_note VARCHAR(255) NULL   -- เหตุผล (บังคับกรอกที่ชั้น Service)
```
**ไม่ควร** บันทึกเป็นแถวใน `payments` ที่ `amount = 0` เพราะ:
- `payments` แปลว่า "เก็บเงินได้" การยกเว้นคือ "ไม่เก็บ" — ปนกันแล้วรายงานรายได้เพี้ยน
- `unique_borrow_payment` จะทำให้ยกเว้นแล้วรับชำระทีหลังไม่ได้ (ซึ่งถูกแล้ว แต่ด้วยเหตุผลผิด)

**5) ผลกระทบต่อข้อมูลเก่า**
ไม่มี — NULL ทั้งหมดแปลว่า "ยังไม่เคยยกเว้น"

**6) ผลกระทบต่อ Report / API / Import / Export**
🔴 **ต้องไล่แก้ทุกที่ที่นิยามคำว่า "ค้างชำระ"** ปัจจุบันคือ
`fine_amount > 0 AND NOT EXISTS(payments)` → ต้องเพิ่ม `AND fine_waived_at IS NULL`
จุดที่ต้องแก้อย่างน้อย: Dashboard การ์ดค้างชำระ · `admin/payments.php` ทั้ง 2 ส่วน ·
`admin/reports.php?report=unpaid` · CSV export · `my_borrows.php` ฝั่งสมาชิก
**ถ้าลืมที่ใดที่หนึ่ง ตัวเลขจะไม่ตรงกันข้ามหน้า — ซึ่งเป็นปัญหาเดิมของ F-35 อยู่แล้ว**

**7) Security / Race condition**
- เป็นเรื่องเงิน → **ต้องบันทึกว่าใครยกเว้น เมื่อไหร่ เพราะอะไร** ทุกครั้ง ห้ามยกเว้นแบบไม่มีเหตุผล
- ควรจำกัดสิทธิ์: admin เท่านั้น หรือ staff ยกเว้นได้ไม่เกินจำนวนหนึ่ง (ให้เจ้าของตัดสิน)
- race: ยกเว้นพร้อมกับรับชำระ → ต้องอยู่ใน transaction + `SELECT ... FOR UPDATE` แถว borrow
  แล้วเช็คซ้ำว่ายังไม่มี payment และยังไม่ถูกยกเว้น

**8) วิธีทดสอบ**
- ยกเว้นแล้ว ยอด "ค้างชำระ" ต้องลดลงทุกหน้าพร้อมกัน (Dashboard / payments / reports / CSV)
- ยกเว้นแล้วกด "รับชำระ" ซ้ำ = ต้องถูกปฏิเสธ
- รับชำระแล้วกด "ยกเว้น" = ต้องถูกปฏิเสธ
- ยิงยกเว้นซ้ำ 3 ครั้ง = ต้องได้ 1 รายการ (แบบเดียวกับที่ payFine ทำได้แล้ว)
- ตรวจว่า `fine_waived_by` ชี้ไปที่คนที่กดจริง

## 3. ต่ออายุการยืม (renew)

**1) ปัญหาคืออะไร**
งานประจำที่ห้องสมุดทำทุกวัน — สมาชิกอ่านไม่จบ ขอต่ออีก 7 วัน
ตารางยืม-คืนมีปุ่มเดียวคือ "คืน"

**2) ตอนนี้ทำอะไรแทน**
คืนแล้วยืมใหม่ — ซึ่ง**ถ้าเลยกำหนดแล้วจะโดนค่าปรับทันที** ทั้งที่ควรได้ต่ออายุ
และประวัติจะกลายเป็น 2 รายการแทนที่จะเป็นรายการเดียวที่ต่ออายุ

**3) ไฟล์ที่ต้องแก้**
- `app/Services/BorrowService.php` — เพิ่ม `renewBorrow(int $borrowId, ?int $days = null)`
- `app/Repositories/BorrowRepository.php` — อัปเดต `due_date` + `renew_count`
- `admin/borrows.php` — ปุ่ม "ต่ออายุ" ในแถวที่ `status = 'borrowing'`
- `my_borrows.php` — (ถ้าเจ้าของอยากให้สมาชิกขอต่อเองได้ — ต้องตัดสินใจก่อน)

**4) Database ต้องเปลี่ยนไหม**
ใช่ — `borrows` เพิ่ม `renew_count TINYINT NOT NULL DEFAULT 0`
และเพิ่มค่าตั้งใน `.env`: `MAX_RENEW_COUNT` (แนะนำ default 1) + `RENEW_DAYS` (default = `DEFAULT_BORROW_DAYS`)

**5) ผลกระทบต่อข้อมูลเก่า**
ไม่มี — default 0 แปลว่ารายการเดิมยังไม่เคยต่ออายุ

**6) ผลกระทบต่อ Report / API / Import / Export**
- รายงาน "หนังสือค้างส่ง" ใช้ `due_date` → ต่ออายุแล้วรายการหลุดจากรายงานทันที (ถูกต้อง)
- สถิติ "จำนวนการยืม" ไม่ควรนับการต่ออายุเป็นการยืมครั้งใหม่ — ตรวจ `reports.php?report=books`
- Dashboard การ์ด "เกินกำหนด" จะลดลงตามจริง

**7) Security / Race condition**
กติกาที่ต้องบังคับ **ที่ชั้น Service** ทั้งหมด:
- 🔴 **ต่อไม่ได้ถ้ามีคนจองเล่มนั้นรออยู่** (`reservations` status `pending`) — เป็นกติกามาตรฐานห้องสมุด
  ถ้าลืมข้อนี้ คนที่จองไว้จะไม่มีวันได้หนังสือ
- ต่อได้ไม่เกิน `MAX_RENEW_COUNT` ครั้ง
- ต่อตอนเลยกำหนดแล้วได้หรือไม่ → **ต้องให้เจ้าของตัดสิน** (ห้องสมุดส่วนใหญ่ให้ต่อได้ต่อเมื่อ
  จ่ายค่าปรับที่ค้างก่อน) เอกสารนี้ยังไม่ตัดสินแทน
- race: ต่ออายุพร้อมกับมีคนกดจอง → transaction + lock แถว book แล้วเช็ค pending ซ้ำในล็อก

**8) วิธีทดสอบ**
- ต่ออายุ → `due_date` ขยับ 7 วัน · `renew_count` = 1 · ค่าปรับที่ค้างไม่หายไป
- ต่อครั้งที่ 2 เมื่อ `MAX_RENEW_COUNT=1` = ถูกปฏิเสธพร้อมข้อความไทย
- มีคนจองเล่มนั้นค้างอยู่ → ต่ออายุ = ถูกปฏิเสธ
- ต่ออายุพร้อมกัน 2 เครื่อง = ขยับครั้งเดียว (แบบเดียวกับที่ทดสอบ F-20 มาแล้ว)
- ตรวจว่า `available` ของหนังสือ **ไม่เปลี่ยน** (ยังถูกยืมอยู่เหมือนเดิม)

## 4. หนังสือหาย / ชำรุด

**1) ปัญหาคืออะไร**
สมาชิกทำหนังสือหาย เป็นเรื่องปกติของห้องสมุด แต่ระบบไม่มีที่ให้บันทึก
และ**ไม่มีแม้แต่ฟิลด์ราคาปกในตาราง `books`** จึงคิดค่าชดใช้ไม่ได้

**2) ตอนนี้ทำอะไรแทน**
ทางอ้อมเดียวคือแก้ไขหนังสือแล้วลดจำนวนลง ซึ่ง
- ไม่ผูกกับสมาชิกคนที่ทำหาย
- ไม่มีการเรียกเก็บเงิน
- และลดไม่ได้จนกว่าจะกดคืนก่อน — ซึ่งการกดคืนจะไปคิดค่าปรับเกินกำหนดแทนค่าหนังสือ
  (ตัวกันทำงานถูกแล้ว: "ไม่สามารถลดจำนวนเป็น 1 ได้ เพราะมีหนังสือออกอยู่ 2 เล่ม (ยืม/จอง)")

**3) ไฟล์ที่ต้องแก้**
- `app/Services/BorrowService.php` — เพิ่ม `markAsLost(int $borrowId, string $condition, ?int $recordedBy)`
- `app/Repositories/BorrowRepository.php` + `BookRepository.php` — ปิดรายการยืม + ลด `quantity`
- `admin/borrows.php` — ปุ่ม "แจ้งหาย/ชำรุด" ข้างปุ่มคืน
- `admin/book_form.php` — ช่อง "ราคาปก"
- `admin/import_books.php` — คอลัมน์ราคา (optional ท้ายสุด)

**4) Database ต้องเปลี่ยนไหม**
ใช่ 2 อย่าง:
```sql
books.price DECIMAL(10,2) NULL          -- ราคาปก (NULL = ไม่ระบุ)
borrows.status ENUM('borrowing','returned','lost','damaged')   -- เพิ่ม 2 ค่า
```
⚠️ การเพิ่มค่าใน ENUM ปลอดภัยกว่าการเปลี่ยนค่าเดิม แต่ **ต้องไล่ดูทุก query
ที่เขียนว่า `status = 'borrowing'` หรือ `status != 'returned'`** ว่ายังหมายถึงสิ่งเดิมหรือไม่

**5) ผลกระทบต่อข้อมูลเก่า**
- `price` เป็น NULL ทั้งหมด → ตอนแจ้งหายต้องให้กรอกราคาเองถ้ายังไม่มี ห้ามคิด 0 เงียบ ๆ
- รายการยืมเก่าไม่มีสถานะใหม่ ไม่กระทบ

**6) ผลกระทบต่อ Report / API / Import / Export**
🔴 **จุดที่อันตรายที่สุดของข้อนี้** — ทุกที่ที่นับ "กำลังยืม" ใช้ `status = 'borrowing'`
ถ้าแจ้งหายแล้วเปลี่ยนเป็น `'lost'` รายการจะหลุดจากทุกรายงานทันที ซึ่งอาจถูกหรือผิดแล้วแต่รายงาน
ต้องไล่ตรวจ: Dashboard (กำลังยืม/เกินกำหนด) · `borrows.php` ตัวกรอง ·
`reports.php` ทั้ง 5 แท็บ · `countActiveBorrows()` ที่ใช้คุมโควตา ·
`my_borrows.php` การ์ดสรุป 4 ใบ

**7) Security / Race condition**
- ลด `quantity` ต้องอยู่ใน transaction เดียวกับการปิดรายการยืม ไม่งั้น invariant พัง
- 🔴 **CHECK constraint `chk_books_quantity_gte_available` จะยิงทันทีถ้าลด quantity ผิดลำดับ**
  ต้องลด `quantity` ลง 1 พร้อมกับที่รายการยืมหายไปจากการนับ ไม่ใช่ลดก่อน
- ค่าชดใช้เป็นเรื่องเงิน → บันทึกว่าใครกด เหมือนข้อ 2
- ต้องตัดสินใจ: ถ้าสมาชิกหาหนังสือเจอทีหลัง จะย้อนกลับได้ไหม (แนะนำให้ได้ แต่ต้องมีร่องรอย)

**8) วิธีทดสอบ**
- แจ้งหาย → `quantity` ลด 1 · `available` ถูกต้อง · **invariant ผ่านทุกเล่ม**
- แจ้งหายเล่มที่ `quantity = 1` → เหลือ 0 ไม่ติดลบ ไม่ชน CHECK constraint
- โควตาของสมาชิกคนนั้นต้องคืนช่อง (ไม่ถูกนับว่ายังยืมอยู่)
- ยิงแจ้งหายซ้ำ 3 ครั้ง = ลด quantity ครั้งเดียว
- ไล่เทียบตัวเลข "กำลังยืม" ทั้ง 6 จุดที่ระบุในข้อ 6 ว่าตรงกันหมด

## 5. จองรอคิวเมื่อหนังสือถูกยืมหมด

> 🔴 **ข้อนี้เสี่ยงที่สุดในทั้ง 5 ข้อ — แตะ invariant สต็อกโดยตรง**
> แนะนำให้ทำหลังสุด และแยก commit ออกจากข้ออื่นทั้งหมด

**1) ปัญหาคืออะไร**
ปุ่มจองมีเฉพาะเล่มที่ยังว่างบนชั้น เล่มที่ `available = 0` ไม่มีปุ่มให้กด
แปลว่าจองได้เฉพาะเล่มที่เดินไปหยิบเองก็ได้ — การจองที่มีประโยชน์จริงคือจองเล่มที่คนอื่นยืมอยู่

**2) ตอนนี้ทำอะไรแทน**
ไม่มี — สมาชิกต้องเดินมาถามเองว่าคืนหรือยัง

**3) ไฟล์ที่ต้องแก้**
- `app/Services/ReservationService.php` — แยก 2 แนวคิดออกจากกันให้ชัด
- `app/Services/BorrowService.php::returnBook()` — ตอนคืนต้องเลื่อนคิว
- `app/Repositories/ReservationRepository.php` — จัดคิว + `markExpiredReservations()` ต้องไม่แตะคิวรอ
- `book.php` — ปุ่ม "เข้าคิวรอ" เมื่อไม่มีเล่มว่าง + แสดงว่าอยู่คิวที่เท่าไร
- `my_reservations.php` — แสดงคิวของตัวเอง
- `admin/reservations.php` — แยกแท็บ "รอมารับ" กับ "รอคิว"

**4) Database ต้องเปลี่ยนไหม**
ใช่:
```sql
reservations.status ENUM('waiting','pending','fulfilled','expired','cancelled')  -- เพิ่ม 'waiting'
reservations.queued_at DATETIME NULL   -- เวลาเข้าคิว (ใช้เรียงลำดับ ไม่ใช้ id เพราะอ่านง่ายกว่า)
```
**แนวคิดที่ต้องแยกให้ขาด:**
| สถานะ | แปลว่า | กินสต็อกไหม |
|---|---|---|
| `waiting` | เข้าคิวรอเล่มที่คนอื่นยืมอยู่ | ❌ **ไม่กิน** |
| `pending` | หนังสือพร้อมแล้ว รอมารับภายใน 2 วัน | ✅ กิน (เหมือนตอนนี้) |

**5) ผลกระทบต่อข้อมูลเก่า**
การจอง `pending` เดิมทั้งหมดยังหมายถึงสิ่งเดิม ไม่ต้องแปลงข้อมูล
แต่ `queued_at` ของแถวเก่าเป็น NULL → เวลาเรียงคิวต้อง `COALESCE(queued_at, created_at)`

**6) ผลกระทบต่อ Report / API / Import / Export**
🔴 **ทุก query ที่นับ `status = 'pending'` ต้องตรวจใหม่ทั้งหมด** ว่าหมายถึง "กินสต็อก"
หรือ "การจองทั้งหมด" จุดที่รู้แล้วว่ามี:
- สูตรสต็อก `available = quantity − ยืมค้าง − จอง pending` — **ห้ามนับ `waiting`**
- `countPending()` ที่ใช้ในการ์ด Dashboard "รอรับของ"
- การนับโควตาสมาชิก (`createBorrow` / `createReservation`) — **ต้องตัดสินใจว่าคิวรอกินโควตาไหม**
  (แนะนำ: **ไม่กิน** เพราะยังไม่ได้หนังสือ แต่ต้องจำกัดจำนวนคิวต่อคนแทน)
- `seed_school_library.php` และชุดทดสอบทั้งหมดที่ยืนยัน invariant

**7) Security / Race condition**
- 🔴 **จุดตายคือตอนคืนหนังสือ** — คืน 1 เล่ม แล้วมีคนรอคิว 3 คน
  ต้องเลื่อนคิวคนแรกเป็น `pending` **ภายใน transaction เดียวกับการคืน**
  ถ้าทำนอก transaction จะเกิดช่วงที่ `available = 1` แล้วมีคนอื่นชิงยืมไปก่อนคนที่รอคิว
- ต้อง `SELECT ... FOR UPDATE` ทั้งแถว book และแถวคิวที่จะเลื่อน
- lazy expire (F-42) ต้องไม่ไปยุ่งกับ `waiting` เพราะคิวรอไม่มีวันหมดอายุ
  — หรือถ้าจะให้หมดอายุ ต้องเป็นคนละกติกา
- ต้องกันคนเข้าคิวซ้ำเล่มเดิม (ตอนนี้ `reservations` ไม่มี UNIQUE กัน pending ซ้ำอยู่แล้ว —
  ดู `KNOWN_LIMITATIONS §4` — ข้อนี้จะทำให้ปัญหาเดิมหนักขึ้น ควรถือโอกาสใส่ UNIQUE ไปด้วย)

**8) วิธีทดสอบ**
- เล่มที่ถูกยืมหมด → เข้าคิวได้ · `available` **ต้องไม่เปลี่ยน**
- คืน 1 เล่ม → คิวคนแรกกลายเป็น `pending` อัตโนมัติ · `available` ยังเป็น 0 (ถูกกันให้คนที่รอ)
- คนที่ไม่ได้อยู่คิวพยายามยืมเล่มนั้นทันทีหลังคืน = ต้องถูกปฏิเสธ
- **ทดสอบแข่งกัน: คืนหนังสือพร้อมกับมีคนยิงยืมเล่มเดิม** → คนที่รอคิวต้องได้
- คิว 3 คน คืน 1 เล่ม → เลื่อนคนเดียว อีก 2 คนยังอยู่คิว
- คนแรกไม่มารับจนหมดอายุ 2 วัน → เลื่อนคนที่ 2 อัตโนมัติ
- **ตรวจ invariant ทุกเล่มหลังทุกเคส** (มีสคริปต์อยู่แล้วใน `seed_school_library.php --verify`)

## เกี่ยวข้องกับข้อค้นพบเดิม

- ข้อ 2 (ยกเว้นค่าปรับ) จะไปแตะนิยาม "ค้างชำระ" ซึ่งเป็นปัญหาเดียวกับ **F-35** — ควรแก้ F-35 ก่อนหรือพร้อมกัน
- ข้อ 3 (ต่ออายุ) และ ข้อ 5 (คิว) ต้องอ่าน **F-42** เรื่อง lazy expire ให้เข้าใจก่อน
- ข้อ 5 จะทำให้ **F-42** ซับซ้อนขึ้นมาก — พิจารณาทำ cron จริงไปพร้อมกัน
- ทุกข้อที่เพิ่มปุ่มใหม่ ควรทำ **F-47** (กล่องยืนยันบอกชื่อของ/ชื่อคน) ไปด้วยเลย
