## 🛒 1. คำถามก่อนซื้อ (Pre-sale)

### 1.1 ระบบนี้ทำอะไรได้บ้าง?

❓ **คำถามลูกค้า:**
> "ระบบนี้ทำอะไรได้บ้างคะ? มีฟีเจอร์อะไรบ้าง?"

✅ **คำตอบที่ควรตอบ:**
> เป็นระบบยืมคืนหนังสือครบวงจรครับ/ค่ะ ฟีเจอร์หลักๆ มี:
> - จัดการหนังสือ (เพิ่ม แก้ ลบ นำเข้าจาก CSV)
> - จัดการผู้ใช้ (สมัคร แก้ไข เปลี่ยน role พิมพ์บัตรสมาชิก นำเข้าจาก CSV)
> - ยืม-คืนหนังสือ พร้อมคำนวณค่าปรับอัตโนมัติ
> - จองหนังสือออนไลน์
> - Dashboard สถิติ + รายงาน + Export CSV + พิมพ์รายงาน (บันทึกเป็น PDF ผ่านกล่องพิมพ์ของเบราว์เซอร์ได้)
> - ระบบ Login แยก admin / staff / member
> - ตั้งค่าชื่อเว็บ ค่าปรับ จำนวนวันยืม ได้เอง
>
> ติดตั้งง่ายด้วย XAMPP กดปุ่มเดียวเลยครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- อย่าพูดเกินจริง — ถ้าลูกค้าถามฟีเจอร์ที่ไม่มี ให้บอกตรงๆ
- ฟีเจอร์ที่ **ไม่มี**: แจ้งเตือน email/LINE จริง, จองแบบเลือกวัน, multi-language, mobile app, payment gateway
- ⚠️ **ห้ามพูดว่า "Export PDF"** — ระบบไม่ได้สร้างไฟล์ PDF ให้
  แต่เปิดหน้าที่จัดรูปแบบมาให้พิมพ์แล้ว ผู้ใช้กด "บันทึกเป็น PDF" ในกล่องพิมพ์ของเบราว์เซอร์เอง
  **สิ่งที่ลูกค้าได้ปลายทางคือไฟล์ PDF เหมือนกัน** แค่ต้องเรียกให้ถูก
  ถ้าลูกค้าถามว่า "กดปุ่มเดียวได้ไฟล์เลยไหม" → ตอบตรง ๆ ว่าต้องผ่านกล่องพิมพ์อีกขั้นหนึ่ง
  (ส่วน **CSV เป็นไฟล์ดาวน์โหลดจริง** กดปุ่มเดียวได้เลย)

### 1.2 เหมาะกับส่งงานอาจารย์ไหม?

❓ **คำถามลูกค้า:**
> "เอาไปส่ง project จบได้ไหมครับ?"

✅ **คำตอบที่ควรตอบ:**
> ได้เลยครับ/ค่ะ หลายคนซื้อไปส่ง project แล้ว ระบบทำงานได้จริง มีฟีเจอร์ครบ มีเอกสารประกอบด้วย
>
> แนะนำว่าซื้อแล้ว **อ่านทำความเข้าใจ flow** ก่อนนะครับ/ค่ะ เผื่ออาจารย์ถามว่า "ส่วนนี้ทำงานยังไง?" จะได้ตอบได้ ในโค้ดมี comment ภาษาไทย + มีเอกสาร FLOW.md อธิบาย flow ทุกขั้นตอน

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- ถ้าลูกค้าถาม "ช่วยอธิบายโค้ดให้ด้วยได้ไหม เวลาสอบ" → อยู่นอกขอบเขต แต่แนะนำให้อ่าน FLOW.md + ARCHITECTURE.md
- ห้ามรับปากว่า "อาจารย์ไม่รู้หรอก" — ไม่มืออาชีพ

### 1.3 ต้องมีพื้นฐานอะไรบ้าง?

❓ **คำถามลูกค้า:**
> "ผมไม่มีพื้นฐานเลย ใช้ได้ไหมครับ?"

✅ **คำตอบที่ควรตอบ:**
> ถ้าแค่ **ติดตั้งและใช้งาน** ไม่ต้องมีพื้นฐานก็ได้ครับ/ค่ะ มีคู่มือติดตั้งทุกขั้นตอน กดตามได้เลย
>
> แต่ถ้าอยากจะ **แก้โค้ดหรือเพิ่มฟีเจอร์** ควรมีพื้นฐาน PHP กับ MySQL บ้างนะครับ/ค่ะ
>
> ข้อดีคือในโค้ดมี comment อธิบายภาษาไทย + มีเอกสารอธิบายโครงสร้าง จะช่วยให้เรียนรู้ไปพร้อมกันได้เลยครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- ถ้าลูกค้าไม่มีพื้นฐานเลยจริงๆ แล้วอยากแก้โค้ด → เตรียมใจรับคำถามเยอะ
- ไม่ต้องปฏิเสธการขาย แต่ตั้ง expectation ให้ชัด

### 1.4 ใช้เทคโนโลยีอะไร?

❓ **คำถามลูกค้า:**
> "ใช้ภาษาอะไร? ต้องลงโปรแกรมอะไรบ้าง?"

✅ **คำตอบที่ควรตอบ:**
> ใช้ PHP + MySQL ครับ/ค่ะ หน้าเว็บใช้ Tailwind CSS + Bootstrap Icons
>
> ลงแค่ **XAMPP** ตัวเดียวก็ใช้ได้เลย (มี PHP + MySQL + Apache มาให้ครบ)
>
> ไม่ต้องลง Node.js, ไม่ต้อง npm, ไม่ต้อง composer ครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- PHP 8.1+ (ทดสอบจริงบน 8.2 และ 8.5), MySQL 5.7+ / MariaDB 10.3+
- Tailwind ใช้แบบคอมไพล์ในเบราว์เซอร์ (ไม่ต้อง build) · ไฟล์เก็บไว้ในโปรเจกต์แล้ว **ใช้งานได้โดยไม่ต่ออินเทอร์เน็ต**
- ไม่ใช้ framework (ไม่ใช่ Laravel, CodeIgniter)

### 1.4.1 ห้องสมุดเราไม่มีอินเทอร์เน็ต ใช้ได้ไหม?

❓ **คำถามลูกค้า:**
> "คอมในห้องสมุดต่อแค่วงในโรงเรียน ไม่ได้ต่อเน็ตข้างนอก ใช้ได้ไหม?"

✅ **ตอบ:**
> ใช้ได้ครับ/ค่ะ ระบบทำงานได้ครบทุกฟีเจอร์โดยไม่ต้องต่ออินเทอร์เน็ต
> ไฟล์ที่ระบบต้องใช้ (ฟอนต์ไทย, ไอคอน, ตัวสร้างบาร์โค้ด/QR, กราฟ) เก็บไว้ในตัวโปรแกรมหมดแล้ว
>
> ขอแค่เครื่องที่ลงระบบกับเครื่องที่ใช้งานอยู่ในวงเดียวกันก็พอ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- เรื่องนี้เคยเป็นปัญหาจริง (F-09) — เดิมโหลดไฟล์จากอินเทอร์เน็ต ถ้าไม่มีเน็ตจะ**ใช้ไม่ได้เลย**
  ไม่ใช่แค่ช้า (หน้าเว็บไม่มี style, พิมพ์บาร์โค้ดไม่ได้, เลือกสมาชิกในหน้ายืมไม่ได้)
- **แก้แล้ว** ตั้งแต่ 2026-08-27 — ยืนยันด้วยการทดสอบว่าไม่มีการเรียกออกภายนอกเลยสักจุด
- สิ่งที่ยังต้องมีเน็ต: ไม่มี · ระบบไม่ส่งอีเมล ไม่เรียก API ภายนอกใด ๆ

## 📬 2. คำถามหลังซื้อ (Post-sale)

### 2.1 ติดตั้งยังไง?

❓ **คำถามลูกค้า:**
> "ซื้อมาแล้ว ต้องทำยังไงต่อ?"

✅ **คำตอบที่ควรตอบ:**
> ทำตามขั้นตอนนี้เลยครับ/ค่ะ:
> 1. ติดตั้ง XAMPP แล้วเปิด Apache + MySQL
> 2. แตกไฟล์วางใน `C:\xampp\htdocs\book_borrowing\`
> 3. ก๊อปปี้ `.env.example` เป็น `.env`
> 4. เปิด browser ไปที่ `http://localhost/book_borrowing/install.php`
> 5. กดติดตั้ง เลือกใส่ข้อมูลตัวอย่างหรือไม่ก็ได้
> 6. เสร็จแล้วเข้าใช้งานได้เลย!
>
> ถ้าติดตรงไหน ทักมาได้เลยนะครับ/ค่ะ พร้อม screenshot จะช่วยได้เร็วขึ้น

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- คำถามนี้ถามบ่อยที่สุด เตรียมคำตอบไว้เลย
- ถ้าลูกค้าใช้ MAMP / Laragon / Docker → อยู่นอกขอบเขต support แต่ช่วยแนะนำได้ถ้าไม่ยาก

### 2.2 login ด้วยอะไร?

❓ **คำถามลูกค้า:**
> "login เข้า admin ด้วยอะไรคะ?"

✅ **คำตอบที่ควรตอบ:**
> ถ้าเลือก "ใส่ข้อมูลตัวอย่าง" ตอนติดตั้ง ใช้ข้อมูลนี้เลยครับ/ค่ะ:
> - Email: admin@library.com
> - Password: password
>
> เข้าหน้า admin ได้ที่: `http://localhost/book_borrowing/admin/`
>
> แนะนำเปลี่ยนรหัสผ่านหลังเข้าระบบครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- ถ้าลูกค้าไม่ได้เลือก import sample data → ต้องสร้าง admin ผ่าน install.php (กรอกเองตอนติดตั้ง)

### 2.3 เปิดแล้วหน้าขาว / error

❓ **คำถามลูกค้า:**
> "เปิดเว็บแล้วหน้าขาวเลยครับ ไม่มีอะไรขึ้น"

✅ **คำตอบที่ควรตอบ:**
> ลองทำตามนี้ครับ/ค่ะ:
> 1. เปิดไฟล์ `.env` แล้วเปลี่ยน `APP_DEBUG=true`
> 2. refresh หน้าเว็บ → จะเห็น error จริงขึ้นมา
> 3. ส่ง screenshot error มาให้ดูได้เลยครับ/ค่ะ
>
> สาเหตุที่พบบ่อย:
> - ยังไม่ได้สร้างไฟล์ `.env` (ก๊อปปี้จาก `.env.example`)
> - ยังไม่ได้รัน `install.php` (ฐานข้อมูลยังไม่ถูกสร้าง)
> - Apache หรือ MySQL ใน XAMPP ยังไม่ได้เปิด

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- คำถามนี้ถามบ่อยอันดับ 2 — 90% แก้ได้ด้วย 3 ข้อข้างบน

---

### 2.4 Database connection failed

❓ **คำถามลูกค้า:**
> "ขึ้นว่า Database connection failed ครับ"

✅ **คำตอบที่ควรตอบ:**
> ลองเช็คตามนี้ครับ/ค่ะ:
> 1. MySQL ใน XAMPP เปิดอยู่หรือเปล่า? (ต้องเห็นไฟเขียว)
> 2. เปิดไฟล์ `.env` ตรวจค่า:
>    - `DB_HOST=localhost`
>    - `DB_NAME=book_borrowing`
>    - `DB_USER=root`
>    - `DB_PASS=` (ปกติ XAMPP จะไม่มี password)
> 3. ลองเปิด phpMyAdmin ดูว่าเข้าได้ไหม → ถ้าเข้าไม่ได้ = MySQL มีปัญหา
>
> ถ้าเช็คแล้วยังไม่ได้ ส่ง screenshot error + ค่าใน `.env` มาให้ดูได้เลยครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- XAMPP บน Mac อาจใช้ socket แทน localhost → ลองเปลี่ยนเป็น `127.0.0.1`
- ถ้าลูกค้าตั้ง password MySQL ไว้ → ต้องใส่ใน `DB_PASS`

---

### 2.5 อยากเปลี่ยนค่าต่างๆ

❓ **คำถามลูกค้า:**
> "เปลี่ยนค่าปรับต่อวันตรงไหนคะ?" / "เปลี่ยนชื่อเว็บยังไง?"

✅ **คำตอบที่ควรตอบ:**
> เปิดไฟล์ `.env` ในโฟลเดอร์โปรเจกต์ แก้ค่าได้เลยครับ/ค่ะ:
> - เปลี่ยนชื่อเว็บ → `APP_NAME="ชื่อใหม่"`
> - เปลี่ยนค่าปรับต่อวัน → `FINE_PER_DAY=20`
> - เปลี่ยนจำนวนวันยืม → `DEFAULT_BORROW_DAYS=14`
> - เปลี่ยนจำนวนเล่มสูงสุด → `MAX_BORROW_BOOKS=5`
>
> แก้แล้ว save → refresh หน้าเว็บ เห็นผลทันทีครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- ถ้าลูกค้าถาม "เปลี่ยนแล้วไม่เห็นผล" → ตรวจว่าแก้ไฟล์ `.env` ไม่ใช่ `.env.example`

---

### 2.6 อยากลบข้อมูลตัวอย่าง

❓ **คำถามลูกค้า:**
> "อยากลบข้อมูลตัวอย่างทั้งหมด เริ่มใหม่จาก 0 ยังไงครับ?"

✅ **คำตอบที่ควรตอบ:**
> วิธีง่ายสุดครับ/ค่ะ:
> 1. เปิด phpMyAdmin → ลบ database `book_borrowing`
> 2. ลบไฟล์ `.installed` ในโฟลเดอร์โปรเจกต์
> 3. เปิด `install.php` ใหม่ → ไม่ต้องเลือก "ใส่ข้อมูลตัวอย่าง"

⚠️ **หมายเหตุสำหรับผู้ขาย:**

### 2.7 login ไม่ได้

### 5.2 รองรับกี่คน?

❓ **คำถามลูกค้า:**
> "ถ้ามีคน 500 คนใช้พร้อมกันได้ไหมครับ?"

✅ **คำตอบที่ควรตอบ:**
> วัดมาแล้วครับ/ค่ะ — **50 คนกดพร้อมกันจริง ๆ ยังตอบภายในไม่ถึง 1 วินาที**
>
> 500 คนพร้อมกันจะหนักเกินไปครับ/ค่ะ ต้องใช้ระบบที่ออกแบบมาสำหรับ traffic สูงโดยเฉพาะ
>
> แต่ถ้า "สมาชิก 500 คน" ที่ไม่ได้เข้าพร้อมกัน → ใช้ได้สบายเลยครับ/ค่ะ
> เพราะคนไม่ได้กดปุ่มพร้อมกันเป๊ะ ๆ ทั้งหมด

⚠️ **หมายเหตุสำหรับผู้ขาย — ตัวเลขนี้วัดจริงแล้ว ไม่ใช่การเดา**

วัดด้วย `php tests/load_test.php` (ยิงพร้อมกันจริงด้วย `curl_multi`) บน XAMPP/macOS:

| กดพร้อมกัน | หน้าแรก (p95) | ค้นหา (p95) | รายละเอียดหนังสือ (p95) | error |
|-----------|--------------|------------|------------------------|-------|
| 10 คน | 23 ms | 101 ms | 17 ms | ไม่มี |
| 30 คน | 48 ms | 292 ms | 44 ms | ไม่มี |
| **50 คน** | **87 ms** | **470 ms** | **66 ms** | **ไม่มี** |
| 100 คน | 200 ms – 2.5 วิ (ไม่เสถียร) | 1.0 วิ | 201 ms | เริ่มมี 503 บางรอบ |

- **≤50 คนพร้อมกัน = ปลอดภัย** ตอบเร็ว ไม่มี error เลยใน 5 รอบทดสอบ
- **100 คนขึ้นไป = เริ่มไม่เสถียร** บางรอบ 200 ms บางรอบ 2.5 วินาที และเริ่มมี 503
- ⚠️ วัดบน localhost ที่ไม่มี network latency · ถ้าลูกค้าเข้าผ่านอินเทอร์เน็ต
  ให้บวกเวลาเน็ตเพิ่ม แต่ขนาดหน้าเว็บอยู่ระดับหลักสิบ KB จึงไม่ใช่ปัญหา
- "ผู้ใช้ 500 คน" ≠ "500 คนพร้อมกัน" → ลูกค้ามักสับสน ต้องถามให้ชัด

### 6.2 จ่ายเพิ่มได้ ช่วยแก้ให้ตรงๆ

❓ **คำถามลูกค้า:**
> "ไม่มีเวลาแก้เอง จ่ายเพิ่มอีก 500 ได้ไหม ช่วยทำให้?"

✅ **คำตอบที่ควรตอบ:**
> ขอบคุณครับ/ค่ะ ถ้าเป็นงานเล็กๆ ที่กำหนดขอบเขตชัดเจน อาจพิจารณาได้ครับ/ค่ะ
>
> ช่วยบอกรายละเอียดว่าต้องการแก้อะไรบ้าง จะประเมินให้ว่าทำได้ไหม ใช้เวลาเท่าไหร่ + ราคาเท่าไหร่ครับ/ค่ะ
>
> ⚠️ งานเสริมจะแยกจาก support ของ template นะครับ/ค่ะ (มี scope + ราคาของตัวเอง)

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- ถ้ารับ → ต้องกำหนด scope + ราคา + timeline ชัดเจนก่อนเริ่มทำ
- ถ้าไม่อยากรับ → ปฏิเสธสุภาพว่า "ตอนนี้รับงาน custom ไม่ได้ครับ"
- อย่ารับด้วยราคาถูกเกินไป → จะไม่คุ้มเวลา

---

### 6.3 เปลี่ยนระบบทั้งหมดเป็นอย่างอื่น

❓ **คำถามลูกค้า:**
> "ถ้าอยากเปลี่ยนจากยืมหนังสือเป็นเช่ารถ ทำได้ไหม?"

✅ **คำตอบที่ควรตอบ:**
> concept คล้ายกัน (ยืม = เช่า, หนังสือ = รถ, สมาชิก = ลูกค้า) ใช้เป็นฐานศึกษาได้ครับ/ค่ะ
>
> แต่ต้องแก้หลายส่วน: ชื่อ field, เงื่อนไขธุรกิจ, หน้าเว็บ, ฐานข้อมูล ซึ่งเป็นงานพัฒนาต่อ ไม่ใช่การตั้งค่า
>
> แนะนำใช้เป็น **แนวทางศึกษา** แล้วแก้ไขเองทีละจุด การแก้ระบบทั้งหมดไม่อยู่ในขอบเขต support ครับ/ค่ะ

⚠️ **หมายเหตุสำหรับผู้ขาย:**
- คำถามนี้ = ลูกค้าอยากได้ระบบใหม่ โดยจ่ายราคา template
- ไม่ต้องรู้สึกผิดที่ปฏิเสธ — ราคา 499 คือค่า template ไม่ใช่ค่า custom development

## 🎯 7. สรุป: เทคนิคตอบแชตแบบมืออาชีพ

### ✅ ทำ

| สถานการณ์ | วิธีตอบ |
|-----------|--------|
| คำถามอยู่ในขอบเขต | ตอบชัด + ให้ขั้นตอน |
| คำถามซ้ำๆ | ส่งลิงก์ไปเอกสาร (FAQ.md, WHERE_TO_EDIT.md) |
| ลูกค้าส่ง error มา | ขอ screenshot + ถามว่าแก้โค้ดอะไรไปบ้าง |
| ลูกค้าขอบคุณ | ตอบสั้นๆ "ยินดีครับ/ค่ะ ถ้ามีอะไรถามได้เลย" |

### ❌ อย่าทำ

| สถานการณ์ | สิ่งที่ห้ามทำ |
|-----------|-------------|
| ลูกค้าขอฟีเจอร์เพิ่ม | ❌ รับปากว่าจะทำให้ฟรี |
| ลูกค้าถามเกิน scope | ❌ ทำเป็นว่าไม่เห็นข้อความ (ตอบปฏิเสธสุภาพแทน) |
| ลูกค้าแก้โค้ดเองแล้วพัง | ❌ รับ debug ให้ทั้งหมด |
| ลูกค้าถามเรื่อง production | ❌ รับปากว่า "ใช้ได้แน่นอน 100%" |
| ลูกค้าขอสอนโค้ด | ❌ กลายเป็น tutor |

### 💬 ประโยคที่ใช้ได้บ่อย

- "ขอบคุณที่ถามครับ/ค่ะ เรื่องนี้ดูในไฟล์ [ชื่อไฟล์] ได้เลย อธิบายไว้ละเอียดครับ/ค่ะ"
- "เรื่องนี้ไม่อยู่ในขอบเขต support ครับ/ค่ะ แต่แนะนำ [ทางเลือก] ครับ/ค่ะ"
- "ส่ง screenshot error มาให้ดูได้เลยนะครับ/ค่ะ จะช่วยตอบได้ตรงจุดกว่า"
- "แนะนำ backup ก่อนแก้อะไรนะครับ/ค่ะ จะได้ย้อนกลับได้ถ้าพัง"
- "ลองเปิด APP_DEBUG=true แล้ว screenshot error มาให้ดูครับ/ค่ะ"
  - ⚠️ **บอกลูกค้าให้ตั้งกลับเป็น `false` ทันทีที่แก้เสร็จ** — เปิดค้างไว้จะเปิดเผย
    รายละเอียดภายในระบบ (เช่น ชื่อผู้ใช้ฐานข้อมูล) ให้คนทั่วไปเห็นตอนเกิด error
    · หน้า error มีคำเตือนนี้แสดงไว้ให้แล้ว
